## 2. Project Background, Purpose & Mental Model

- **Purpose.** T3 Code lets people run their coding agents on a local or remote workspace from a common UI. It wraps provider CLIs and protocols, and the host retains the workspace, provider credentials, agent processes, and thread state. The user can reopen or control the same environment from a phone, desktop, or browser. The fork branch `mine` follows upstream and carries Ben's product work and workflow changes.
- **Surfaces.** `apps/web` serves both the hosted and server-hosted web client. `apps/desktop` is Electron with the web renderer, trusted preload IPC, and an optional bundled local server. `apps/mobile` is React Native with native iOS and Android presentation and its own navigation. The clients share connection, state, permission, and presentation logic where practical. The host can be reached directly by LAN or VPN, through a route such as SSH where supported, or through T3 Connect.
- **Request lifecycle.** Typed WebSocket RPCs cross the contracts boundary. The server maps a request to a command. `Orchestrator.ts` decides the events without I/O, and the event sink commits events, projections, receipts, and outbox work together. The effect worker executes provider starts, checkpoints, and other effects after commit, then feeds results back as commands. The UI reads projections and local draft state. A turn can complete with a hidden Git checkpoint ref so changes can be diffed or restored.
- **Provider boundary.** Each adapter translates its runtime's native protocol into common turn items, usage, and lifecycle data. Provider capabilities determine which choices the UI offers. Usage for a model step, occupied context, billing counts, and a compaction event are distinct measurements. Keep provider-specific interpretation at the adapter boundary and use common display logic where it preserves meaning.
- **Terminology.** An environment is a running T3 server and the state and credentials it owns. A project is a workspace record in one environment. A thread is the saved conversation and work history. A run or turn records a unit of agent work. No Project uses the environment's managed scratch workspace. A Quick Question can be a real thread hidden from ordinary sidebar and search views until the user promotes it. T3 home is the base directory above `userdata`.
- **Scope.** Keep state, permissions, and connection behavior consistent across local and remote clients. Preserve existing product wording and UI conventions. The fork backlog records Ben's open work and the divergence log records completed dispositions and evidence. The prior implementation included no store publishing, live server changes, deployment, or PR.
